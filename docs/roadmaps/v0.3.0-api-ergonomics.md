# v0.3.0: the API-ergonomics batch

> **Status: PARKED** (2026-09-21), deliberately. Every item here is a breaking change, none is
> urgent, and they are worth strictly more done together than scattered across releases: one
> semver event, one migration note, one `cargo-semver-checks` run that the CHANGELOG is written
> from. Deferring them is what kept v0.2.0 reviewable.

Found during the v0.2.0 review passes (`docs/audit/V0_2_0_AUDIT_2026-09-20.md`). Correctness
findings from those passes were fixed in v0.2.0; what is left here is ergonomics and API shape.

Nothing below is a defect. Everything below is a shape that lets a caller write a plausible,
compiling, wrong call.

## 1. Transposable positional parameters

The recurring hazard: adjacent parameters of the same type, where a transposition compiles and
returns a wrong answer rather than an error.

| site | signature | why a swap is silent |
|---|---|---|
| `OthelloGptConfig::new` | 5 consecutive `usize` then a `bool` | only `n_embd % n_head == 0` is checked, which most transpositions pass. The crate's own doctest uses `n_layer == n_head == 8`, so it cannot demonstrate the order |
| `DoseResponseCurve::add_point` | 3 consecutive `f32` | no validation is possible. `DoseResponsePoint` already has these three named fields: take it by value |
| `SteeringCalibration::new` | 2 adjacent `f32`, then 2 adjacent `usize` | two independent swap sites in one call |
| `AttentionCache::top_attended_positions` and siblings | `(layer, position)` | the two most-confusable indices in mechanistic interpretability; both small, so a swap usually lands in range |
| `create_generation_mask` | 3 sequence-ish `usize` | `new_seq_len == 1` is an early-return fast path, so a swap escapes it and builds the wrong mask |
| `pca_top_k` | `(k, n_iter)` | `k=10, n_iter=3` and `k=3, n_iter=10` are both ordinary calls |
| `RnnWeights::new` | 3 consecutive `Vec<f32>` | guarded by `assert_eq!`, but the `weight_hh`/`weight_oh` swap passes every assert when `output_size == hidden_size` |
| `forward_fast_traced` | 2 adjacent `&mut [f32]` out-params | a swap writes each result into the other's buffer |

**Result constructors are the sharpest case.** `AblationResult::new(baseline, treated, ..)` and its
four siblings take two adjacent `Tensor`s whose order decides the answer: `kl_divergence` is
asymmetric (`KL(P || Q)`), and `top_changed_tokens`' signed deltas invert. `MemoryReport::new(before,
after)` is worse in consequence, since the deltas are `after - before` and a transposition makes a
leak read as a free.

`GenerationResult::new` (added in v0.2.0) documents its own ordering rationale for three adjacent
`String`s. That comment is an admission that the type-level fix is owed.

**The single highest-value refactor here:** six public `validate` methods on one conceptual spec
family take the same model dimensions in **three arities and two orders** --
`(n_layers, n_heads, seq_len)`, `(n_layers, seq_len, d_model)`, `(n_layers, seq_len)` -- all called
with bare integers. One `ModelDims` struct collapses all six and removes the whole class.

## 2. Boolean parameters that should be enums

- `cosine: bool` at four sites in `src/clt/mod.rs`, where call sites read `.., 20, true)`. The flag
  is load-bearing, not a tweak. `enum SimilarityMetric { DotProduct, Cosine }`.
- `normalise: bool` as the 7th positional argument of `build_contrastive_direction`.
- `causal: bool` as the 6th of `OthelloGptConfig::new`, whose own doc comment already spells out
  the two variants in prose.

## 3. One duplication cluster left

v0.2.0 consolidated six clusters; `src/interp/intervention.rs` is the seventh and largest. Five
result types hand-write the same three wrapper methods over the same two shared helpers. The
*implementations* are already shared, so what is duplicated is roughly 120 lines of wrappers and
identical doc comments -- **plus an asymmetry the duplication hides**: two of the five silently lack
`logit_diff`.

A `trait LogitComparison { fn baseline(&self) -> &Tensor; fn treated(&self) -> &Tensor; }` with the
three methods as provided defaults collapses it and fixes the asymmetry. Removing the inherent
methods is the breaking half. Field names can stay domain-specific (`ablated_logits`,
`steered_logits`, `injected_logits`); only the accessor needs to be uniform.

## 4. Reproducibility: `sample_token` cannot be seeded

`MIModel::sample_token` uses `rand::thread_rng()` and offers no way to pass a seed, so the crate's
flagship public sampler is unreproducible at any `temperature > 0`. For an interpretability crate
that is a real gap, and fixing it is a signature change.

Three RNG policies currently coexist: `thread_rng()` here, a seeded `StdRng` in
`diffusion::sample` (self-documented as a deliberate choice to revisit), and the frozen `ChaCha8`
of `util::rng`, which exists precisely because `rand` does not promise `StdRng` reproducibility
across releases. Settle on one.

Adjacent: `backend.rs` and `diffusion/sample.rs` carry two independent hand-rolled
stable-softmax-plus-categorical-draw loops, down to the same float-edge-case comment. One shared
helper.

## 5. Visibility and naming drift

- `apply_scale_steering` / `apply_set_value_steering` have no caller but `apply_steering` and are
  not root-re-exported: make them `pub(crate)`. Both also carry a dead `_n_heads` parameter,
  underscore-prefixed and ignored, in a *public* signature.
- `diffusion::rope` is `pub mod` while `transformer::rope` is `pub(crate) mod`. The diffusion side
  is out of step with the crate's own precedent, and demoting it removes an accidental public type.
- `clt::gemmascope::parse_gemmascope_config` is a public YAML text parser. Not part of a
  mechanistic-interpretability crate's contract.
- Three verbs for "load from a `HuggingFace` repo id": `MIModel::from_pretrained`,
  `Sae::from_pretrained`, and the outlier `CrossLayerTranscoder::open`, which reads like a file
  handle but spawns a tokio runtime and hits the API.
- `GenericRwkv::load` takes two parameters it discards (`_device`, `_dtype`), purely to match a
  shape it does not need.
- Five items in `interp::intervention` are not root-re-exported while their 16 peers are, which
  looks accidental rather than chosen.

## 6. Construction ergonomics, the other half of the v0.2.0 work

v0.2.0 marked 47 structs `#[non_exhaustive]`, which is correct, but **six of the seven public config
types have no public constructor at all** -- `TransformerConfig`, `RwkvConfig`, `MdlmConfig`,
`CltConfig`, `SaeConfig` and `RwkvLoraDims` expose only `from_hf_config(&serde_json::Value)`. A
downstream user who wants a small or custom config must hand-write a JSON blob.

`OthelloGptConfig` (`new` plus three `with_*`) and `StoicheiaConfig` (`from_task`) are the
exceptions, and they are the shape to copy.

This is also what stops the synthetic test rigs below from being usable *outside* the crate, which
is an argument for doing the two together.

## Not in this batch, tracked elsewhere

- **Synthetic test rigs** for `GenericTransformer`, `GenericMdlm` and `GenericRwkv`. Non-breaking,
  so it need not wait for v0.3.0, but it belongs with item 6 because the rigs are only useful
  downstream if configs are constructible. `GenericTransformer` first: it unlocks the first unit
  tests for `attention.rs`, `mlp.rs`, `norm.rs` and `rope.rs` at once.
- **`KVCache`** -- inherited from plip-rs, where it was live in every `forward_*`. Orphaned by
  candle-mi's redesign around one hook-aware forward. Decide: delete, or demote to `pub(crate)`
  with a doc that stops promising O(1)-per-token generation the crate does not implement.
- **The `metal` feature**, which nothing has ever compiled. See `docs/metal-preflight.md`.

## How to run this batch

Do it as one commit series with `cargo-semver-checks` against the last published version, and write
the CHANGELOG's breaking list from its output rather than by hand. v0.2.0 established that the tool
catches struct and signature changes but **not** a public const's type changing, so the machine list
is necessary and not sufficient.
